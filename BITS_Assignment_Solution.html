Step 4: Undo Operation using Git

To demonstrate an undo operation on a commit:

  1. I made an additional commit by adding a temporary file experimental.html: 
    git add experimental.html
git commit -m "Add experimental feature for undo testing"
# [main e265a46] Add experimental feature for undo testing
  2. I then undid this commit using git revert HEAD --no-edit: 
    git revert HEAD --no-edit
# [main 21aec47] Revert "Add experimental feature for undo testing"
# 1 file changed, 11 deletions(-)
# delete mode 100644 experimental.html
  3. Effect on repository state:
    • The file experimental.html was automatically deleted from the working tree (verified with Test-Path experimental.html returning False).
    • Working directory is clean (git status reports nothing to commit, working tree clean).
    • Why I chose git revert: In Git, git revert is the recommended undo operation for public and shared repositories because it creates an inverse commit without rewriting history. This ensures the undo action is transparently verified on GitHub's commit log. (Alternatively, git reset HEAD~1 can be used locally, but that rewinds HEAD and deletes the commit from the branch history).

# Git Command Brief Explanation
1 git init -b main Initializes a new local Git repository inside the project folder with 'main' as default branch.
2 git status Displays the state of the working directory and staging area, highlighting untracked or modified files.
3 git add . Stages all new, modified, and deleted files in the working directory for the upcoming commit.
4 git commit -m "Initial commit..." Records the staged snapshot of index.html and about.html into repository history.
5 git add index.html Stages modifications made specifically to index.html for the second commit.
6 git commit -m "Update index.html..." Creates the second commit on the main branch, recording changes made to index.html.
7 git branch feature Creates a new branch named 'feature' branching off from the current commit of the main branch.
8 git switch feature (or git checkout) Switches the active working branch from 'main' to 'feature', updating HEAD and working tree.
9 git branch Lists all local branches in the repository and marks the currently active branch with an asterisk (*).
10 git add about.html Stages modifications made to about.html while working on the isolated 'feature' branch.
11 git commit -m "Enhance about.html..." Records the commit containing the new about.html content directly onto the 'feature' branch.
12 git switch main Switches the active branch back to 'main' in preparation for integrating the feature branch changes.
13 git merge --no-ff feature -m "..." Merges the 'feature' branch into 'main' using a dedicated merge commit (--no-ff) to preserve branch history.
14 git log --graph --oneline --all Displays a compact graphical view of commit history across all branches showing divergence and merge points.
15 git status --ignored Displays working directory status including files deliberately ignored according to rules defined in .gitignore.
16 git add .gitignore Stages the newly created .gitignore file containing exclusion rules for *.log and temp/.
17 git commit -m "Configure .gitignore..." Records .gitignore into version control history so that ignore rules are tracked and shared.
18 git add experimental.html Stages a temporary experimental file created specifically to demonstrate an undo operation.
19 git commit -m "Add experimental..." Records the experimental commit that will subsequently be undone.
20 git revert HEAD --no-edit Undoes the previous commit safely by creating an inverse commit, removing experimental.html while preserving history.
21 git reset HEAD~1 (Alternative Undo) Moves HEAD and branch pointer back by one commit; used locally when commits have not yet been pushed to remote.
22 git remote add origin <url> Associates the local Git repository with the remote public repository hosted on GitHub.
23 git remote -v Lists all configured remote connections along with their fetch and push target URLs.
24 git push -u origin main Pushes the complete 'main' branch commit history to GitHub and establishes upstream tracking.
25 git push -u origin feature Pushes the local 'feature' branch to GitHub so all branching history and commits are visible remotely.
Question 2: Test Case Design

Application Scenario: Testing a Login System with inputs Username, Password, and a Login button.

Functional Requirements:

  1. Username must not be empty.
  2. Password must be at least 6 characters long.
  3. Valid username and password allow a successful login.
  4. Invalid credentials should display an error message.
  5. After 3 consecutive failed login attempts, the account should be locked.
Test Design Approach: Designed using Equivalence Partitioning (valid vs. invalid input partitions), Boundary Value Analysis (testing password lengths at 0, 5, 6, and >6 characters), and State Transition testing for the 3-attempt account lockout mechanism.
